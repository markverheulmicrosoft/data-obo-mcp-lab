Het hele plaatje

Eén gebruiker, meerdere controles

Elke laag beantwoordt een andere vraag. Een toegestane tool is nog geen toegestane tabel.

Browser

02 / TOOLRECHTEN

MCP-gateway

Valideert het JWT en de approl. Niet toegestaan? De tool stopt hier.

03 / DELEGATIE

04 / DATARECHTEN

Fabric Warehouse

Itemtoegang, SQL SELECT en RLS bepalen of — en welke — data terugkomt.

Architectuuroverzicht, geen gesimuleerde uitvoeringstrace. Hieronder meten we alleen de werkelijke totale aanroeptijd; er zijn geen verzonnen deeltijden of afgeronde stappen.

Vier gerichte experimenten

Verwachten is niet hetzelfde als zien

Begin bij 1. Elke knop verstuurt een echte aanvraag. Vergelijk daarna dezelfde stappen met een ander account.

1

Wie ben ik voor de gateway?

Vraag de aangeboden tools op en laat de gateway de getekende gebruikersidentiteit, rollen en bronconfiguratie beschrijven.

2

Welke orders zie ik?

Dezelfde query, een andere gebruiker. North verwacht 3 Noord-rijen; Finance verwacht alle 6. De rijen worden door Fabric RLS gefilterd.

3

De gateway laat door. De bron ook?

North én Finance mogen deze tool aanroepen. North mist aanvankelijk SQL SELECT op marges: de verwachte weigering komt uit Fabric.

4

Wat blokkeert de gateway zelf?

Dezelfde margesquery, maar nu met Finance-rolcontrole vóór de bron. Deze knop doet een directe aanroep, óók als discovery de tool niet toont.

    Houd de lagen uit elkaar

    Vier rechten die je niet moet verwarren

    Gateway

    Mag ik deze tool gebruiken?

    De approl North.Reader of Finance.Reader komt uit het gevalideerde access token. De gateway kan een tool blokkeren zonder een SQL-query uit te voeren.

    Fabric-item

    Mag ik het item benaderen?

    Fabric Read geeft itemtoegang. Dat is niet automatisch SELECT op elke tabel. Brede workspace-rollen of aanvullende ReadData-rechten kunnen de test beïnvloeden.

    SQL-tabel

    Mag ik deze tabel lezen?

    SQL SELECT bepaalt tabeltoegang. Voor de margestabel is dat aanvankelijk alleen Finance. North mag de tool wel vragen, maar de bron weigert.

    Rijen

    Welke rijen krijg ik te zien?

    Row-level security filtert rijen ná succesvolle toegang tot de tabel. North ziet Noord; Finance ziet ook Zuid. De bron dwingt dit af, niet de browser.

    Controleer buiten de gateway

    Open de echte bron

    De echte Fabric-itemlink verschijnt pas na aanmelden én een geslaagde describe_access-aanroep. We verzinnen geen bron-URL.

    Open Fabric Warehouse ↗

    Open in Fabric de SQL-editor van dezelfde Warehouse, als exact dezelfde gebruiker, en voer daar de overeenkomstige query uit. Dan test je dezelfde SQL-rechten en RLS.

    Een Lakehouse-, OneLake- of bestandsroute is geen gelijkwaardige RLS-test: die kan buiten deze Warehouse-SQL-beveiliging vallen. Controleer ook het account in het Fabric-portaal.

    Wisselen & opnieuw proberen

    Verander de gebruiker, niet het verhaal

    1. Kies Ander account en selecteer echt een ander Microsoft-account. Oude identiteit, gegevens en waarnemingen worden direct gewist.
    2. Voer de vier experimenten opnieuw uit. De verwachting wordt gekoppeld aan de gatewayrollen, niet aan een gekozen persona.
    3. Laat rechten alleen wijzigen via het Fabric-portaal of SQL. Dit scherm heeft geen beheerdersachterdeur.
    4. Na nieuwe grants, consent of rolwijzigingen: wacht op propagatie, meld af en heropen de client. Een bestaand token kan nog oude rollen bevatten.

    Een beheeraccount is geschikt voor inrichting, niet voor bewijs van beperkte gebruikersrechten. Gebruik aparte North- en Finance-testaccounts.
